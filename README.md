# Transfer Grokking — Geometry Transfer Experiments

[![Code DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.21142333.svg)](https://doi.org/10.5281/zenodo.21142333)
[![Preprint DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.21100971.svg)](https://doi.org/10.5281/zenodo.21100971)
[![ORCID](https://img.shields.io/badge/ORCID-0009--0001--2717--732X-a6ce39?logo=orcid&logoColor=white)](https://orcid.org/0009-0001-2717-732X)

**Core question:** Can a grokked transformer's modular arithmetic circuit (discrete Fourier features) be transferred to an LLM's residual stream?

**Headline result:** Yes — training a linear projection via cross-entropy through the frozen lm_head, then injecting at the last layer (L31 for Phi-2) at full strength (α=1.0), achieves perfect task accuracy. The transition from baseline to perfect accuracy is a sharp threshold compressed into Δα ≈ 0.05 (a steep but continuous S-curve — the "discontinuous override" of v2.0.0 was a coarse-grid artifact). Full details in [`docs/FINDINGS.md`](docs/FINDINGS.md). Phase-by-phase narrative of the 9 dead ends that preceded this result is also there.

## Quick start: use our pre-trained result

Loads the committed grokked model checkpoint and runs the full pipeline. No training needed — the model weights come from LFS.

```bash
git lfs pull                          # fetch grokked weights from LFS
source .venv/bin/activate

python run_pipeline.py                # all 7 steps, seeds 42-46, ops add+mult
```

Or step by step (single seed shown for brevity; steps 1-6 reproduce the v2.0.0 paper,
step 7 the v3.0.0 margin-analysis correction):

```bash
# Steps 1-6: reproduce v2.0.0 paper result
python src/pipeline/cache_activations.py add
python src/pipeline/cache_activations.py mult
python src/pipeline/ce_projection.py 42 add
python src/pipeline/ce_projection.py 42 mult
python src/pipeline/l31_patch.py 42 add
python src/pipeline/l31_patch.py 42 mult
python src/pipeline/eval_l31_perplexity.py "42" add
python src/pipeline/eval_l31_perplexity.py "42" mult
python src/pipeline/cross_model_probe.py
python src/pipeline/random_baseline.py 42 add --partial
python src/pipeline/random_baseline.py 42 mult --partial

# Step 7: v3.0.0 correction analysis (supersedes the coarse-grid interpretation)
python src/pipeline/margin_analysis.py "42" add
python src/pipeline/margin_analysis.py "42" mult
```

Phi-2 weights (`microsoft/phi-2`) load from Hugging Face Hub on first run; revision `810d367871c1d460086d9f82db8696f2e0a0fcd0` is pinned for reproducibility. All scripts run from the repo root.

## Verify training from scratch (optional, ~4 hours CPU)

Not part of the main pipeline — the committed LFS checkpoint is the source of truth. Only run this if you're auditing whether the training procedure itself converges correctly (e.g. after changing `train_small.py`). See `docs/FINDINGS.md` for what correct convergence looks like.

```bash
# Train small model (+ and × mod 97) — ~90 min CPU total
python src/pipeline/train_small.py add    # ~30k epochs (~30 min)
python src/pipeline/train_small.py mult   # ~100k epochs (~60 min)

# Then run the standard pipeline on the freshly trained weights
python run_pipeline.py
```

## Known limitations

- The L31 injection is a **sharp threshold**: α<1.0 provides near-zero task accuracy at coarse resolution (the transition is a steep S-curve compressed into Δα≈0.05, previously mischaracterized as a "hard override"). The norm-mismatch mechanism is understood (see Finding #12 in `docs/FINDINGS.md`) but a practical fix is future work.
- Cross-model comparison via lm_head is impossible for models whose tokenizers split multi-digit numbers (Qwen2-Math, most BPE models). The `cross_model_probe.py` script bypasses this with a probe on injected hidden states instead.
