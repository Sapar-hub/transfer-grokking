# Transfer Grokking — Geometry Transfer Experiments

[![Code DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.21142333.svg)](https://doi.org/10.5281/zenodo.21142333)
[![Preprint DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.21100972.svg)](https://doi.org/10.5281/zenodo.21100972)
[![ORCID](https://img.shields.io/badge/ORCID-0009--0001--2717--732X-a6ce39?logo=orcid&logoColor=white)](https://orcid.org/0009-0001-2717-732X)

**Core question:** Can a grokked transformer's modular arithmetic circuit (discrete Fourier features) be transferred to an LLM's residual stream?

**Headline result:** Yes — training a linear projection via cross-entropy through the frozen lm_head, then injecting at the last layer (L31 for Phi-2) at full strength (α=1.0), achieves perfect task accuracy. This is a discontinuous override: intermediate α leaves model behavior statistically indistinguishable from baseline. Full details in [`docs/FINDINGS.md`](docs/FINDINGS.md). Phase-by-phase narrative of the 9 dead ends that preceded this result is also there.

## Quick start: use our pre-trained result

Loads the committed grokked model checkpoint and Phi-2 (no training needed).

```bash
git lfs pull                          # fetch grokked weights from LFS
source .venv/bin/activate

# Sanity check: model learned Fourier features
python src/verify_fourier.py

# Cache activations + train projection → L31 patch → results (seconds each)
python src/pipeline/cache_activations.py add
python src/pipeline/cache_activations.py mult
python src/pipeline/ce_projection.py 42 add
python src/pipeline/ce_projection.py 42 mult
python src/pipeline/l31_patch.py 42 add
python src/pipeline/l31_patch.py 42 mult
python src/pipeline/eval_l31_perplexity.py "42" add
python src/pipeline/eval_l31_perplexity.py "42" mult
python src/pipeline/cross_model_probe.py
python src/pipeline/random_baseline.py 42 add --partial
python src/pipeline/random_baseline.py 42 mult --partial
```

Phi-2 weights (`microsoft/phi-2`) load from Hugging Face Hub on first run; revision `810d367871c1d460086d9f82db8696f2e0a0fcd0` is pinned. All scripts run from the repo root.

## Verify training from scratch (optional, ~4 hours CPU)

Only needed if you're auditing the training procedure itself. Uses the committed checkpoint for the grokked model; no retraining.

### All at once

```bash
bash run_pipeline.sh
```

### Step by step

```bash
# Step 1: Train small model (+ and × mod 97)
python src/pipeline/train_small.py add    # ~30k epochs (~30 min)
python src/pipeline/train_small.py mult   # ~100k epochs (~60 min)

# Steps 2–7: same as quick start above (cache → CE → patch → eval → controls)
python src/pipeline/cache_activations.py add
…
```

Training is CPU-only and takes the bulk of the time. Once model checkpoints exist, all downstream steps run in seconds. `run_pipeline.sh` automates the full 7-step, 5-seed sequence with skip-on-cache.

## Known limitations

- The L31 injection is a **hard override**: α<1.0 provides no task accuracy or perplexity benefit. The norm-mismatch mechanism is understood (see Finding #12 in `docs/FINDINGS.md`) but a fix is future work.
- Cross-model comparison via lm_head is impossible for models whose tokenizers split multi-digit numbers (Qwen2-Math, most BPE models). The `cross_model_probe.py` script bypasses this with a probe on injected hidden states instead.
